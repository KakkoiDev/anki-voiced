# anki-voiced

Build Japanese Anki decks with pitch accent, per-kanji furigana, Edge TTS audio, and a 3-card listening/reading/cloze design.

## Pipeline (slug-based decks)

```
decks/<slug>/
  deck.toml                     # name, model_id, deck_base_id, tiers
  tier1-vocabulary.csv          # 9-column schema (see below)
  tier1-audio/                  # generated by `anki-voiced audio`
  ...
```

Commands:

```sh
anki-voiced init <slug>                     # scaffold decks/<slug>/
anki-voiced validate --deck <slug>          # check CSV (no network)
anki-voiced pitch --deck <slug>             # generate PitchAccent column (UniDic)
anki-voiced audio  --deck <slug>            # Edge TTS -> tier{N}-audio/*.mp3
anki-voiced create --deck <slug>            # build <slug>-complete.apkg
anki-voiced decks                           # list configured decks
anki-voiced voices                          # show Edge TTS voices
```

One-shot build from a CSV (bypasses slug layout):

```sh
anki-voiced create path/to/file.csv -o out.apkg
```

## CSV schema (9 columns, exact names, case-sensitive)

| Column       | Purpose                                     | Example |
|--------------|---------------------------------------------|---------|
| Sentence     | Japanese sentence (display form)            | `会議【かいぎ】は10時【じ】です。` |
| Translation  | English translation                         | `The meeting is at 10.` |
| Cloze        | Key word (used for card 3 and pitch accent) | `会議` |
| Pronunciation| Dual-purpose display + TTS input            | same as Sentence, usually |
| Note         | Category/tag (shown as a chip on cards)     | `Business - Meetings` |
| Register     | casual \| polite \| formal \| keigo         | `polite` |
| KeyMeaning   | English gloss of the Cloze                  | `meeting` |
| PitchAccent  | Auto-generated colored ruby HTML            | (leave blank, run `pitch`) |
| Audio        | `[sound:tierN_NNN.mp3]`                     | (leave blank, run `audio`) |

Required on authoring: Sentence, Translation, Cloze, Pronunciation, KeyMeaning. The rest are generated or optional.

## Furigana rules (critical)

Per-kanji annotation is the source of truth. The annotation goes on the kanji ONLY, not over trailing hiragana (okurigana).

Correct:
```
食【た】べる
取【と】り組【く】む
忘【わす】れ物【もの】
残【のこ】り物【もの】
```

Wrong:
```
食べる【たべる】       ← furigana covers okurigana, breaks card display
取り組む【とりくむ】   ← same issue; breaks pitch accent matching
```

Ideographic iteration mark 々 is handled: `徐々【じょじょ】に` works.

Digits are preserved: `2日【にち】` renders as `2日` with furigana.

## TTS quality (Edge TTS)

Default voice is `ja-JP-KeitaNeural` (male). `--female` uses `ja-JP-NanamiNeural`.

Pipeline automatically:
- `は` (particle) -> `わ` (before furigana extraction, while brackets disambiguate)
- `を` -> `を、` for natural pause after object marker
- `が` -> `が、` when context says subject marker (skips ありがとう, ながら, 方がいい, verb stems like 上がる)
- Introductory adverbs (`まず`, `次に`, `実は`, etc.) get `、` after
- English acronyms/terms: 300+ entries in `preprocessing/acronyms.py` (`API -> エーピーアイ`, `EC2 -> イーシーツー`)
- `%` -> パーセント, `v2` -> バージョン2

### Fixing TTS misreadings

Some kanji Edge TTS reads wrong in isolation (`型` becomes がた not かた). Fix:

1. Add the kanji to `TTS_KANJI_OVERRIDES` in `src/anki_voiced/preprocessing/acronyms.py`
2. Keep the CSV Pronunciation as `漢字【reading】` (do NOT edit CSV)
3. Run `anki-voiced audio --deck <slug> --force` to regenerate

NEVER replace kanji with kana directly in the CSV. The Pronunciation field drives the card display with ruby HTML. Replacing kanji destroys that.

### Irregular counters

`2日 = ふつか`, `1人 = ひとり`, etc. Write kana directly in the Pronunciation field because the digit "2" otherwise reads as "ni":

Wrong: `2日【ふつか】` -> TTS says "ni futsuka"
Right: `ふつか` in Pronunciation (and `2日` in Sentence for display)

### English loanwords

For loanwords best read as katakana (webhook, README), write katakana directly in Pronunciation (`ウェブフック`, `リードミー`). Don't rely on acronym map for these.

## Register system

Use `Register` to tag speech politeness level. Gets a colored badge on the Reading card and Listening card back.

| Value   | Use case |
|---------|----------|
| casual  | Friends, family, informal |
| polite  | Work, customers, default |
| formal  | Presentations, announcements |
| keigo   | Customer service, job interviews, superiors |

Not enforced (won't fail validation) but strongly recommended for pedagogy.

## 3-card model

Each note generates 3 cards:

1. **Listening**: Big play button, no text. Back shows furigana + translation + register + key word with pitch.
2. **Reading**: Plain sentence, no audio. Back shows furigana + translation + audio + key word.
3. **Vocabulary**: Sentence with Cloze word blanked (JS). Back highlights the answer.

Separation prevents reading-along during listening and tests single-vocab recall instead of whole-sentence memorization.

## Common mistakes

- Annotating hiragana: `ありがとう【ありがとう】` is wrong. Hiragana needs no furigana.
- Compound cloze without matching Pronunciation: if `Cloze=協力する` and `Pronunciation=協力【きょうりょく】して`, the pitch extractor handles it (dictionary form vs inflected). If it still can't match, verify the cloze substring actually appears in Pronunciation.
- Empty KeyMeaning: validation errors. Every Cloze needs an English gloss.
- Mixing `取り組む【とりくむ】` and `取【と】り組【く】む` in the same file: normalize to per-kanji form.
- Editing CSV to fix TTS: use `TTS_KANJI_OVERRIDES` instead.

## When authoring from a vocabulary list

Given a plain vocabulary list (e.g. `reservation\nmeeting\nlunch`), produce CSV rows:

1. Pick a natural sentence that contains the target word
2. Add furigana per-kanji: `予約【よやく】したいのですが。`
3. Fill Cloze with the dictionary form: `予約`
4. KeyMeaning: `reservation`
5. Note: category like `Restaurant` or `Business - Meetings`
6. Register: `polite` by default
7. Leave PitchAccent and Audio empty - the pipeline fills them

Then: `validate` -> `pitch` -> `audio` -> `create`.
